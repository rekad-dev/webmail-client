# Harness Setup Flow

Use this only when the user asks to create or substantially revise the harness.

1. Read existing harness files and the project brief first.
2. Identify task types, authoritative documents, workflow, confirmation boundaries, and current repository structure.
3. Ask only about choices that materially affect the harness and are not already answered in the user's brief.
4. Agree on the file set before introducing new layers, automation, or project-specific skills.
5. Keep the root AGENTS.md short and route detail into _harness/.
6. Review links, paths, status data, and rule consistency after generation.

Do not add unrelated skills or copy project-specific policies from a reference repository.
